# 편입/임시점용 조서 산출 프로그램

QGIS를 직접 열지 않고 `지적도 SHP`, `도로/점용 경계 SHP(선택)`, `관로 SHP`, `도곽 SHP/DXF(선택)`, `법정동코드 또는 행정구역 매핑 XLSX/CSV`를 입력받아 편입면적과 임시 점용 관련 값을 계산하고 `조서 원본`, `DATA` 시트용 결과를 `CSV`와 `XLSX`로 생성하는 독립 실행형 Python 프로그램입니다.

현재 메인 프로그램은 토공 원본(`토공 엑셀 + 관로공 엑셀`) 또는 기존 전처리 결과(`산정입력 + 관로라인`)를 함께 받아, 전처리와 본 산정을 한 번에 이어서 실행할 수 있습니다.

이번 1차 범위에는 다음이 포함됩니다.

- 필드명 고정 없이 사용자 필드 매핑 지원
- geometry 유효성 검사 및 보정 시도
- 좌표계 확인 및 투영 좌표계 기준 면적 계산
- 편입 대상 필지 교차 분석 및 동일 필지 집계
- 임시 점용 폭/면적 계산
- Excel/CSV 출력
- 관로 좌표계 기준 CAD 중첩용 DXF 출력
- 한국어 로그 및 오류 메시지

이번 범위에서 제외된 항목은 AutoCAD 자동삽입, 도면 출력, DWG 직접 작성입니다.

## 공통 엔진 준비

현재 버전에는 다음 단계 확장을 위한 `가시설/구조물 공통 엔진`의 기본 규칙 테이블이 포함되어 있습니다.

- `pipe`: 기존 관로
- `valve_chamber`: 밸브실
- `manhole`: 맨홀
- `shoring_zone`: 가시설 구간

설정 위치는 `config/default_config.json`의 `common_occupancy_engine.feature_rules`입니다. 이번 단계에서는 규칙 정의와 검증 뼈대만 포함하며, 실제 구조물 SHP 입력과 가시설 구간 반영은 다음 단계에서 확장합니다.

```

```

### CLI 실행

```bash
python main.py run \
  --cadastral path/to/cadastral.shp \
  --boundary path/to/boundary.shp \
  --facility path/to/facility.shp \
  --sheet path/to/sheet.dxf \
  --code-file path/to/codes.xlsx \
  --output-dir path/to/output
```

선택 인자:

- `--config`: 사용자 설정 JSON 경로
- `--soil-cover`: 토피(m)
- `--pavement`: 포장상태
- `--excavation-slope`: 터파기 기울기
- `--main-line-reverse`: 메인관로 번호 방향을 역방향으로 처리
- `--earthwork-file`: 토공 원본 엑셀 경로(선택)
- `--pipe-workbook`: 관로공 엑셀 경로(선택)
- `--earthwork-input`: 기존 산정입력 CSV/XLSX 경로(선택)
- `--earthwork-lines`: 기존 관로라인 CSV/XLSX 경로(선택)

토공 입력 방식은 아래 두 가지 중 하나만 선택합니다.

- 원본 자동연결: `--earthwork-file` + `--pipe-workbook`
- 전처리 결과 재사용: `--earthwork-input` + `--earthwork-lines`

## 토공 전처리기

토공 수량산출서 원본은 형식 편차가 크므로, 본 산정기에 바로 넣기보다 먼저 `토공 전처리기`로 표준 테이블로 변환하는 것을 권장합니다.

현재 버전은 루트의 `토공샘플_2.xlsx`, `관로공샘플.xlsx`, `상수관로(국골)_5187.shp`와 같은 구조를 기준으로 아래 흐름으로 동작합니다.

- 토공 파일:
  - 메인관로는 `visible` 상태의 `토적산출표(*-LINE)` 시트에서 읽음
  - 지선은 `visible` 상태의 `관로토공LIST(*)` 시트에서 읽음
  - `변실LIST`, 대표단면 시트도 함께 읽음
- 관로공 파일: `visible` 상태의 `관수량(직관)` 시트에서 라인명/측점/연장 읽음
- 관로 SHP: 라인 길이와 geometry 후보, 분기점/후보 검토 정보를 함께 요약

전처리기는 다음 정보를 표준화합니다.

- 관로 라인 목록
- 토공 구간(`시점거리/종점거리/구간연장/절단연장`)
- 포장상태(`아스팔트/콘크리트/비포장`으로 정규화)
- 시공환경(`육상`, `수중` 등)
- 도로폭 구분
- 대표단면 후보 시트
- 기본 설정 기준 터파기폭(`터파기폭(m)`)
- 구조물 목록
- 관로 SHP 길이 후보 매칭
- 검토 필요 사유

주의:

- 숨김 시트는 읽지 않습니다.
- `C-LINE`처럼 메인관로는 `토적산출표`, 그 외 지선은 `관로토공LIST`를 우선 사용합니다.
- 현재 샘플 토공파일의 `규격`, `4.5M이상`, `2.5M~4.5M` 같은 값은 굴착깊이가 아니라 도로폭 구분으로 해석합니다.
- 따라서 현재 전처리기는 이 값만으로 `가시설 필요 여부`를 확정하지 않습니다.
- 연장 우선순위는 `관로 SHP -> 관로공 -> 토공 누적연장`입니다.
- 관경은 `D63(50)`, `D90(75)`처럼 괄호가 있으면 괄호 안의 공칭/내경 값을 우선 적용합니다.
- `관매달기`는 `임시점용적용=아니오`, `영구점용적용=예`로 표준화합니다.
- `육상`, `수중`은 포장상태가 아니라 `시공환경`으로 따로 보존합니다.
- `산정입력` 시트의 `터파기폭(m)`은 현재 조서 산정기 기본값(`토피`, `포장상태`, `터파기기울기`) 기준의 예비 폭입니다.
- `포장상태`가 비어 있고 `시공환경`만 있는 구간은 `산정포장상태`에 계산용 기본값이 기록됩니다.
- `중리1-2-LINE`, 길이 62m 중복 후보처럼 자동으로 단정하기 어려운 항목은 `검토필요` 시트로 남깁니다.

## 입력 데이터 형식

필수 입력:

- 지적도 SHP
- 도로/점용 경계 SHP(선택)
- 관로 SHP
- 도곽 SHP 또는 DXF(선택, 권장)
- 법정동코드 또는 행정구역 매핑 XLSX 또는 CSV

선택 입력:

- 사용자 설정 JSON
- 토공 원본 엑셀 + 관로공 엑셀
- 또는 기존 전처리 결과(`산정입력`, `관로라인`)

도곽을 DXF로 입력하는 경우 DXF에는 좌표계 정보가 없으므로, 프로그램은 상수관로 SHP와 동일한 좌표계를 사용한다고 가정합니다.

### SHP 구성 파일 주의사항

Shapefile은 최소한 다음 파일이 같은 폴더에 있어야 합니다.

- `.shp`
- `.shx`
- `.dbf`

`.prj`도 함께 두는 것을 권장합니다. 좌표계 정보가 없으면 분석을 진행할 수 없습니다.

## 필드 매핑 방법

입력 데이터의 필드명은 고정하지 않습니다.

1. GUI에서 SHP 2개와 행정구역 파일 1개를 선택합니다.
2. `필드 자동 추정` 버튼을 누릅니다.
3. 자동 추정 결과를 검토한 뒤 필요한 필드를 콤보박스에서 직접 선택합니다.
4. `설정 저장`을 누르면 현재 매핑과 옵션을 JSON으로 저장할 수 있습니다.

기본적으로 다음 논리 필드를 사용합니다.

- 지적도: `PNU`, `지번/JIBUN`
- 관로: `관경`
- 행정구역 파일: `행정구역 코드`

다음 필드는 자동 추정만 시도하고 UI에서는 숨깁니다.

- 지적도: `지목`, `소유구분`, `행정구역코드`
- 관로: `연장`, `관로종류`
- 행정구역 파일: `행정구역명`, `시도명`, `시군구명`, `읍면동명`, `동리명`

조서원본의 `시도`, `시군구`, `읍면동`, `리`는 다음 순서로 채웁니다.

1. 지적도의 `행정구역코드`가 있으면 우선 사용합니다.
2. 없으면 `PNU` 앞 10자리를 법정동코드로 사용합니다.
3. 코드 파일에 `시도명`, `시군구명`, `읍면동명`, `동리명`이 있으면 그 값을 직접 사용합니다.
4. 위 개별 컬럼이 없으면 코드 파일의 `행정구역명`을 이용해 `시도`, `시군구`, `읍면동`, `리`를 분해합니다.

지적도의 `지번/JIBUN` 필드는 기존 QGIS 정리 스크립트와 비슷하게 처리합니다.

- `1-1 전`처럼 지번과 지목이 한 칼럼에 같이 들어 있으면 `지번=1-1`, `지목=전`으로 분리합니다.
- 별도 `지목` 필드가 있으면 그 값을 우선 사용합니다.
- `공부면적`은 지적도 폴리곤의 투영좌표계 면적을 사용합니다.

## 임시 점용 산출 조건 설명

GUI에서 아래 3개 항목을 반드시 드롭다운으로 선택합니다.

- 토피: `1.2` ~ `2.0`, `0.1m` 간격
- 포장상태: `아스팔트`, `콘크리트`, `비포장`
- 터파기 기울기: `1:0.3`, `1:0.5`, `1:0.7`, `1:1`, `1:1.2`, `1:1.5`

기본값:

- 토피 `1.2m`
- 포장상태 `아스팔트`
- 터파기 기울기 `1:0.3`

현재 버전의 임시 점용 폭 계산식은 기존 QGIS 스크립트의 폭 식을 기준으로, 드롭다운 선택값을 보정 반영하는 방식입니다.

```text
기준 바닥폭 = 관경(m) + 0.40 + 포장상태 보정폭
기준 깊이 = 0.90 + 관경(m) + (선택 토피 - 기본 토피 1.2m)
임시점용폭 = ceil_0.1(기준 바닥폭 + 2 × 기울기비 × 기준 깊이)
```

즉, 기본 선택값 `토피 1.2m / 아스팔트 / 1:0.3`에서는 기존 QGIS 스크립트의 임시점용 폭과 최대한 같게 맞추고, 사용자가 토피·포장상태·기울기를 바꾸면 그 값이 폭과 면적에 직접 반영됩니다.

면적 산정은 QGIS 처리 로직과 동일하게 버퍼 기반으로 수행합니다.

```text
영구점용폭 = max(기본 영구점용폭, 관경(m))
영구점용면적 = 관로 영구점용 버퍼 ∩ 선택적 도로/점용 경계 ∩ 지적도 면적

임시점용폭 = 위 드롭다운 선택값을 반영해 계산
임시점용면적 = (관로 임시점용 버퍼 - 관로 영구점용 버퍼) ∩ 선택적 도로/점용 경계 ∩ 지적도 면적
```

즉, 도로/점용 경계 SHP는 필수 기준이 아니라 선택적 클리핑 레이어입니다. 경계를 선택하지 않으면 관로 버퍼를 그대로 지적도와 교차해 산정하며, 일반적으로 이 경우 경계를 적용했을 때보다 면적이 더 크게 나오는 것이 정상입니다.

설정값 위치:

- 기본 터파기 바닥폭: `config/default_config.json`
- 포장상태별 추가폭: `config/default_config.json`
- 드롭다운 선택지: `config/default_config.json`

출력 결과와 로그에는 최소한 다음 값이 남습니다.

- 적용 토피
- 적용 포장상태
- 적용 터파기 기울기
- 산출된 임시 점용 폭
- 산출된 임시 점용 면적

`DATA` 시트에는 위 기본 컬럼 외에 `법정동코드`, `토피(m)`, `포장상태`, `터파기기울기`, `임시점용폭(m)`이 추가됩니다.

### CAD DXF 출력

CAD 중첩용 DXF는 상수관로 SHP의 좌표계를 그대로 사용합니다.

한글 지번과 지목이 포함될 수 있으므로 DXF 본문은 `cp949(ANSI_949)`로 저장합니다. AutoCAD와 ZWCAD 호환을 위한 설정입니다.

- 도곽 레이어: `YJ_SHEET`
- 지적도 레이어: `YJ_PARCEL`
- 지번 레이어: `YJ_LOTNO`
- 영구점용 레이어: `YJ_PERM`
- 임시점용 레이어: `YJ_TEMP`
- 조서번호 레이어: `YJ_REG_NO`
- 조서번호 연결선 레이어: `YJ_REG_LEADER`

현재 DXF는 다음 요소를 포함합니다.

- 도곽 폴리곤 경계
- 지적도 경계
- 지번 내부 대표점 문자
- 영구점용 폴리곤 경계
- 임시점용 폴리곤 경계
- 조서번호 원형 표기
- 조서번호 문자
- 임시점용 대표점과 조서번호를 잇는 연결선

임시점용 레이어는 `임시점용 버퍼 - 영구점용 버퍼` 기준의 실제 임시점용 면적 결과입니다.

즉, 최종 설계도면에 바로 얹어볼 수 있는 오버레이 DXF를 만드는 것이 현재 목표이며, AutoCAD 자동삽입은 아직 포함하지 않습니다.

조서번호는 기존 QGIS 스크립트 흐름을 따라 임시점용 geometry를 기준으로 관로 진행방향 순서대로 부여합니다. 프로그램은 관로 네트워크에서 가장 긴 경로를 메인관로로 자동 추정하고, 나머지 연결 구간은 지선관로로 자동 그룹화합니다. 메인관로는 GUI의 `메인관로 방향` 선택값에 따라 `시점→종점` 또는 `종점→시점`으로 번호를 매기고, 지선관로는 메인관로와 만나는 분기점에서 말단 방향으로 번호를 부여합니다. 임시점용 geometry가 없는 필지는 그 뒤에 일반 정렬 순서로 배치합니다.

## 임시파일과 백업

프로그램은 실행 시 프로젝트 루트의 `.runtime_temp` 폴더만 임시작업 폴더로 사용합니다.

- 시작 시 이전 실행에서 남은 `.runtime_temp` 내부 파일을 자동 정리합니다.
- 시작 시 루트에 남아 있는 랜덤 임시파일과 `verify_case*`, `__pycache__`, `.codex_tmp`도 함께 정리합니다.
- 종료 시 현재 세션 임시파일도 자동 정리합니다.
- 종료 시에도 같은 기준으로 루트 임시찌꺼기를 한 번 더 정리합니다.

버전 백업은 아래 스크립트로 생성합니다.

```bash
python tools/create_backup.py
```

실행하면 `##backup/verN` 형식으로 다음 버전 폴더가 생성되며, 소스/설정/테스트만 복사하고 임시폴더와 캐시는 제외합니다.

## 자주 발생하는 오류와 해결 방법

- `파일을 찾을 수 없습니다`
  - 입력 경로가 올바른지 확인합니다.
- `SHP 구성 파일이 누락되었습니다`
  - `.shp`, `.shx`, `.dbf`가 모두 있는지 확인합니다.
- `CSV 파일을 읽지 못했습니다`
  - UTF-8, UTF-8-SIG, CP949, EUC-KR 인코딩을 순차 시도합니다. 다른 인코딩이면 다시 저장해 주세요.
- `필드 매핑이 필요합니다`
  - GUI의 필드 매핑 콤보박스에서 필요한 논리 필드를 직접 지정합니다.
- `좌표계 정보가 없습니다`
  - `.prj`가 있는지 확인하고 좌표계를 부여한 뒤 다시 실행합니다.
- `geometry invalid`
  - 프로그램이 자동 보정을 시도합니다. 보정 실패 객체는 오류목록으로 빠집니다.
- `편입 대상 필지가 없습니다`
  - 도로/점용 경계와 지적도가 실제로 겹치는지 확인합니다.
- `출력 파일 저장에 실패했습니다`
  - 엑셀 파일이 열려 있는지, 출력 폴더 권한이 있는지 확인합니다.
  - 프로그램은 엑셀 저장 시 작업 폴더 내부 임시폴더를 사용하므로 한글 사용자 계정 경로에서도 저장 실패 가능성을 줄였습니다.
- `중복 PNU`
  - 자동 집계는 수행되지만 원본 데이터 정합성은 별도 검토를 권장합니다.

## Windows 배포 가이드

현재 권장 배포 방식은 `PyInstaller onedir + Inno Setup`입니다.

배포용 파일은 모두 루트 폴더의 `배포용` 안에 정리되어 있습니다.

- 포터블 빌드: `배포용\build_portable.bat`
- 설치파일 빌드: `배포용\build_installer.bat`
- 전체 빌드: `배포용\build_all.bat`
- PyInstaller spec: `배포용\app_release.spec`
- Inno Setup 스크립트: `배포용\installer.iss`
- 배포 안내: `배포용\배포안내.md`

빌드 PC 준비:

```bash
pip install -r requirements.txt
pip install -r 배포용/build_requirements.txt
```

포터블 버전 생성:

```bat
배포용\build_portable.bat
```

설치파일 생성:

```bat
배포용\build_installer.bat
```

최종적으로 사용자에게 전달할 파일:

- 가장 권장: `배포용\output\installer\YonggidoRegister_setup_버전.exe`
- 설치파일이 없을 때 권장 대안: `배포용\output\release\YonggidoRegister_portable.zip`
- 폴더째 전달해야 할 때: `배포용\output\release\YonggidoRegister_portable` 폴더 전체

배포 시 권장 사항:

- 루트 폴더의 `YongJIdo.ico`를 실행 파일과 설치 아이콘으로 사용합니다.
- Windows x64 환경에서 빌드하고 검증한 뒤 배포합니다.
- 실제 SHP/XLSX 입력 데이터로 1회 이상 최종 검증 후 배포합니다.
